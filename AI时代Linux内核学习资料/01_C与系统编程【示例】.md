## 本章目标

这四周不追求掌握所有 C 语法，而是掌握内核开发真正依赖的能力：精确理解对象布局和生命周期、识别未定义行为、读懂编译链接结果、正确处理系统调用的失败与部分完成。

## 第 1 周：对象、指针与内存

### 概念地图

- **对象与存储期**：automatic、static、allocated、thread-local。
- **值与表示**：有符号溢出、大小端、对齐、padding、strict aliasing。
- **指针**：指向对象、越界规则、函数指针、`void *`、`const` 的位置。
- **结构体**：布局受 ABI 与对齐影响，不能凭字段大小相加猜测 `sizeof`。
- **宏**：参数可能求值多次；多语句宏需要安全包裹；类型检查弱。
- **生命周期**：拥有者、借用者、引用计数、释放后引用。

### 实验 1：结构体与容器

定义一个包含 `char`、`int`、指针和嵌套结构体的类型，打印每个字段 `offsetof`、结构体 `sizeof` 和 `_Alignof`。改变字段顺序，对比大小；使用 `pahole` 观察空洞。

思考：内核为何经常通过重新排列字段减少 cache footprint？为什么 ABI 结构体不能随意调整？

#### 实操步骤

1. 进入第 1 周目录，创建 `layout.c`：

```c
#include <stddef.h>
#include <stdio.h>

struct point {
    short x;
    short y;
};

struct record_a {
    char tag;
    int count;
    void *data;
    struct point pos;
    char valid;
};

struct record_b {
    void *data;
    int count;
    struct point pos;
    char tag;
    char valid;
};

#define SHOW(type, member) \
    printf("%-20s offset=%2zu size=%2zu\n", #member, \
           offsetof(type, member), sizeof(((type *)0)->member))

int main(void)
{
    printf("record_a: sizeof=%zu align=%zu\n",
           sizeof(struct record_a), _Alignof(struct record_a));
    SHOW(struct record_a, tag);
    SHOW(struct record_a, count);
    SHOW(struct record_a, data);
    SHOW(struct record_a, pos);
    SHOW(struct record_a, valid);

    printf("record_b: sizeof=%zu align=%zu\n",
           sizeof(struct record_b), _Alignof(struct record_b));
    SHOW(struct record_b, data);
    SHOW(struct record_b, count);
    SHOW(struct record_b, pos);
    SHOW(struct record_b, tag);
    SHOW(struct record_b, valid);
    return 0;
}
```

### 实验 2：实现简化版侵入式链表

不要把数据复制进链表节点，而是在业务对象内嵌 `list_node`，再用 `offsetof` 从成员指针反推容器地址。随后阅读 `include/linux/list.h` 中的 `container_of` 和 list API，比较你的实现遗漏了哪些类型检查与边界处理。

#### 实操步骤

1. 创建 `ilist.c`，先实现节点、初始化、尾插、删除和容器转换：

```c
#include <stddef.h>
#include <stdio.h>

struct list_node {
    struct list_node *prev;
    struct list_node *next;
};

#define LIST_HEAD(name) struct list_node name = { &(name), &(name) }
#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))
#define list_entry(ptr, type, member) container_of(ptr, type, member)

static void list_add_tail(struct list_node *node, struct list_node *head)
{
    node->prev = head->prev;
    node->next = head;
    head->prev->next = node;
    head->prev = node;
}

static void list_del(struct list_node *node)
{
    node->prev->next = node->next;
    node->next->prev = node->prev;
    node->next = NULL;
    node->prev = NULL;
}

struct task {
    int pid;
    const char *name;
    struct list_node runq;
};

int main(void)
{
    struct task tasks[] = {
        { .pid = 101, .name = "alpha" },
        { .pid = 102, .name = "beta" },
        { .pid = 103, .name = "gamma" },
    };
    LIST_HEAD(head);

    for (size_t i = 0; i < sizeof(tasks) / sizeof(tasks[0]); i++)
        list_add_tail(&tasks[i].runq, &head);

    for (struct list_node *p = head.next, *next; p != &head; p = next) {
        next = p->next;
        struct task *t = list_entry(p, struct task, runq);
        printf("pid=%d name=%s task=%p node=%p\n",
               t->pid, t->name, (void *)t, (void *)p);
        if (t->pid == 102)
            list_del(p);
    }

    for (struct list_node *p = head.next; p != &head; p = p->next) {
        struct task *t = list_entry(p, struct task, runq);
        printf("remaining: %d\n", t->pid);
    }
    return 0;
}
```

### 实验 3：让工具发现错误

分别制造：heap buffer overflow、use-after-free、double free、signed overflow、data race。用户态用以下组合构建：

```bash
cc -O1 -g -Wall -Wextra -Werror \
  -fsanitize=address,undefined demo.c -o demo
```

数据竞争单独使用 ThreadSanitizer：

```bash
cc -O1 -g -fsanitize=thread -pthread race.c -o race
```

记录检测器报告的第一处错误、分配栈、访问栈，而不是只保存最后一行。

#### 实操步骤

1. 创建 `memory_bugs.c`，用命令行参数保证每次只触发一种错误：

```c
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void heap_overflow(void) { char *p = malloc(8); p[8] = 'x'; free(p); }
static void use_after_free(void) { int *p = malloc(sizeof(*p)); free(p); printf("%d\n", *p); }
static void double_free(void) { void *p = malloc(8); free(p); free(p); }
static void signed_overflow(void) { volatile int n = INT_MAX; printf("%d\n", n + 1); }

int main(int argc, char **argv)
{
    if (argc != 2) {
        fprintf(stderr, "usage: %s overflow|uaf|double-free|signed\n", argv[0]);
        return 2;
    }
    if (!strcmp(argv[1], "overflow")) heap_overflow();
    else if (!strcmp(argv[1], "uaf")) use_after_free();
    else if (!strcmp(argv[1], "double-free")) double_free();
    else if (!strcmp(argv[1], "signed")) signed_overflow();
    else return 2;
    return 0;
}
```

2. 构建并分别运行；不要在一次运行中将多种错误混在一起：

```bash
cc -O1 -g3 -fno-omit-frame-pointer -Wall -Wextra \
  -fsanitize=address,undefined memory_bugs.c -o memory_bugs
ASAN_OPTIONS=halt_on_error=1 ./memory_bugs overflow
ASAN_OPTIONS=halt_on_error=1 ./memory_bugs uaf
ASAN_OPTIONS=halt_on_error=1 ./memory_bugs double-free
UBSAN_OPTIONS=print_stacktrace=1 ./memory_bugs signed
```

3. 对每份报告标注：错误类型、第一个业务源码栈帧、非法访问大小、目标对象的分配/释放栈。修复该错误并确认报告消失。
4. 创建 `race.c`：

```c
#include <pthread.h>
#include <stdio.h>

static int counter;
static void *worker(void *arg)
{
    (void)arg;
    for (int i = 0; i < 100000; i++)
        counter++;
    return NULL;
}

int main(void)
{
    pthread_t a, b;
    pthread_create(&a, NULL, worker, NULL);
    pthread_create(&b, NULL, worker, NULL);
    pthread_join(a, NULL);
    pthread_join(b, NULL);
    printf("counter=%d\n", counter);
    return 0;
}
```

5. 单独构建 TSan 版本，记录两个冲突访问所在线程和源码行：

```bash
cc -O1 -g3 -fno-omit-frame-pointer -fsanitize=thread \
  -pthread race.c -o race
./race
```

6. 用 `pthread_mutex_t` 保护 `counter++`，再运行 TSan。最后将 `counter` 仅改成 `volatile`，验证 TSan 仍会报告竞争，说明 `volatile` 不是同步原语。

**完成标准**：五种错误各有一份报告摘要和一个已验证的修复。若当前平台不支持 TSan，在报告中记录限制，不要把“无报告”当成“无竞争”。

## 第 3 周：进程、文件描述符与虚拟内存

### 进程闭环

- `fork()` 复制的是进程执行上下文视图，物理页通常借助 COW 延后复制。
- `execve()` 替换当前进程映像，不创建新进程。
- `waitpid()` 回收子进程退出状态，避免 zombie。
- 文件描述符是进程表中的索引；dup 后多个 fd 可指向同一个 open file description。

每个 syscall 都可能失败。用户态代码至少处理：返回值、`errno`、`EINTR`、部分读写、资源回收。

### 实验 1：fork/exec/wait

父进程创建管道，fork 后子进程把 stdout 重定向到管道并 exec `/bin/uname`，父进程读取输出并 wait。验证以下错误路径：exec 文件不存在、父进程提前关闭、read 被 signal 中断。

#### 实操步骤

1. 进入 `~/lab/c-sys/week3`，创建 `pipe_exec.c`：

```c
#include <errno.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/wait.h>
#include <unistd.h>

static void die(const char *what) { perror(what); exit(EXIT_FAILURE); }
static void on_alarm(int signo) { (void)signo; }

int main(int argc, char **argv)
{
    int fd[2];
    if (pipe(fd) == -1) die("pipe");

    pid_t pid = fork();
    if (pid == -1) die("fork");
    if (pid == 0) {
        if (close(fd[0]) == -1) _exit(120);
        if (dup2(fd[1], STDOUT_FILENO) == -1) _exit(121);
        if (close(fd[1]) == -1) _exit(122);
        const char *path = argc > 1 ? argv[1] : "/bin/uname";
        char *const child_argv[] = { (char *)path, "-a", NULL };
        execv(path, child_argv);
        dprintf(STDERR_FILENO, "execv %s: %s\n", path, strerror(errno));
        _exit(127);
    }

    if (close(fd[1]) == -1) die("close write end");
    struct sigaction sa = { .sa_handler = on_alarm };
    sigemptyset(&sa.sa_mask);
    if (sigaction(SIGALRM, &sa, NULL) == -1) die("sigaction");

    char buf[128];
    for (;;) {
        ssize_t n = read(fd[0], buf, sizeof(buf));
        if (n > 0) {
            for (ssize_t off = 0; off < n;) {
                ssize_t w = write(STDOUT_FILENO, buf + off, (size_t)(n - off));
                if (w > 0) off += w;
                else if (w == -1 && errno == EINTR) continue;
                else die("write");
            }
        } else if (n == 0) {
            break;
        } else if (errno != EINTR) {
            die("read");
        }
    }
    close(fd[0]);

    int status;
    while (waitpid(pid, &status, 0) == -1) {
        if (errno != EINTR) die("waitpid");
    }
    if (WIFEXITED(status)) printf("child exit=%d\n", WEXITSTATUS(status));
    else if (WIFSIGNALED(status)) printf("child signal=%d\n", WTERMSIG(status));
    return 0;
}
```

2. 编译、运行并跟踪系统调用：

```bash
cc -std=c11 -D_POSIX_C_SOURCE=200809L -O1 -g3 \
  -Wall -Wextra -Werror pipe_exec.c -o pipe_exec
./pipe_exec
strace -f -e trace=process,pipe,dup2,close,read,write ./pipe_exec
```

3. 检查 `strace` 中的顺序：`pipe → fork/clone → dup2 → execve → read → wait4`，并确认父子两边都关闭了不再使用的 pipe fd。
4. 执行 `./pipe_exec /no/such/program`，验证子进程将 `errno` 写入 stderr，父进程收到退出码 127。
5. 为验证“读端提前关闭”，把子命令替换为会持续输出的 `/usr/bin/yes`，让父进程读一次后关闭 `fd[0]`。观察子进程被 `SIGPIPE` 终止或写入收到 `EPIPE`。实验后恢复程序。
6. 为验证 `EINTR`，在父进程进入 `read` 前执行 `alarm(1)`，并让子进程在 exec 前 `sleep(2)`。因为信号处理器没设 `SA_RESTART`，首次 `read` 应返回 `-1/EINTR`；可临时加日志确认重试分支被执行。

**完成标准**：正常路径、exec 失败、`SIGPIPE/EPIPE` 和 `EINTR` 四种路径均有记录；运行结束后 `ps` 中无遗留 zombie。

### 实验 2：COW

#### 实操步骤

1. 先记录环境：

```bash

```

2. 创建 `cow.c`：

```c
#define _GNU_SOURCE
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <sys/resource.h>
#include <sys/wait.h>
#include <unistd.h>

static void usage(const char *who)
{
    struct rusage r;
    if (getrusage(RUSAGE_SELF, &r) == -1) { perror("getrusage"); exit(1); }
    printf("%s pid=%ld minflt=%ld majflt=%ld\n",
           who, (long)getpid(), r.ru_minflt, r.ru_majflt);
    fflush(stdout);
}

int main(void)
{
    const size_t len = 256UL * 1024 * 1024;
    const long page = sysconf(_SC_PAGESIZE);
    unsigned char *p = mmap(NULL, len, PROT_READ | PROT_WRITE,
                            MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }

    for (size_t i = 0; i < len; i += (size_t)page) p[i] = 1;
    usage("before-fork");
    pid_t pid = fork();
    if (pid == -1) { perror("fork"); return 1; }
    if (pid == 0) {
        usage("child-before-write");
        for (size_t i = 0; i < len / 2; i += (size_t)page) p[i]++;
        usage("child-after-write");
        printf("inspect child now; sleeping 20s\n");
        fflush(stdout);
        sleep(20);
        _exit(0);
    }

    printf("parent=%ld child=%ld; sleeping 10s\n", (long)getpid(), (long)pid);
    fflush(stdout);
    sleep(10);
    usage("parent-after-child-write");
    int status;
    while (waitpid(pid, &status, 0) == -1 && errno == EINTR) {}
    munmap(p, len);
    return 0;
}
```

3. 构建后在终端 A 运行，记下打印的父子 PID：

```bash
cc -O2 -g3 -Wall -Wextra -Werror cow.c -o cow
./cow
```

4. 在 20 秒窗口内，在终端 B 用真实 PID 查看：

```bash
parent_pid=1234  # 替换为程序打印的真实 PID
child_pid=1235   # 替换为程序打印的真实 PID
rg '^(Rss|Pss|Pss_Anon|Private_Dirty|Shared_Dirty):' "/proc/$parent_pid/smaps_rollup"
rg '^(Rss|Pss|Pss_Anon|Private_Dirty|Shared_Dirty):' "/proc/$child_pid/smaps_rollup"

```

5. 用 `perf` 重复至少 5 次：

```bash

```

若无 `perf` 权限，保留 `getrusage` 和 `/proc` 数据即可，不要为了这个实验盲目放宽全局安全设置。

6. 分别把子进程写入范围改为 0%、25%、50%、100%，对比 minor faults 与 PSS。如需研究 THP，先用 `madvise(..., MADV_NOHUGEPAGE)` 与 `MADV_HUGEPAGE` 做进程级对照，不要直接改全局 THP 配置。

**完成标准**：报告包含至少 5 次数据、页大小、THP 状态和负载，并能区分 RSS 与 PSS，不把 `fork()` 后的虚拟地址复制误解成所有物理页立即复制。

### 实验 3：文件映射

比较 `read/write` 与 `mmap` 修改文件：什么时候内存变化可见？`msync`、`fsync` 各保证什么？异常退出时哪些假设不成立？本实验只对临时文件执行。

#### 实操步骤

1. 在 `~/lab/c-sys/week3` 创建专用临时文件，确认它不是重要数据：

```bash
tmpfile=$(mktemp /tmp/mmap-lab.XXXXXX)
printf '0123456789abcdef\n' > "$tmpfile"
ls -li "$tmpfile"
od -An -tx1c "$tmpfile"
```

2. 创建 `map_edit.c`，通过参数选择 `MAP_SHARED` 或 `MAP_PRIVATE`：

```c
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <sys/stat.h>
#include <unistd.h>

int main(int argc, char **argv)
{
    if (argc != 3 || (strcmp(argv[1], "shared") && strcmp(argv[1], "private"))) {
        fprintf(stderr, "usage: %s shared|private FILE\n", argv[0]);
        return 2;
    }
    int fd = open(argv[2], O_RDWR);
    if (fd == -1) { perror("open"); return 1; }
    struct stat st;
    if (fstat(fd, &st) == -1) { perror("fstat"); return 1; }
    int flags = !strcmp(argv[1], "shared") ? MAP_SHARED : MAP_PRIVATE;
    char *p = mmap(NULL, (size_t)st.st_size, PROT_READ | PROT_WRITE, flags, fd, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }
    memcpy(p, "MMAP", 4);
    printf("mapped bytes now: %.8s; press Enter before msync\n", p);
    getchar();
    if (msync(p, (size_t)st.st_size, MS_SYNC) == -1) perror("msync");
    printf("msync done; press Enter to exit\n");
    getchar();
    munmap(p, (size_t)st.st_size);
    close(fd);
    return 0;
}
```

3. 编译并在终端 A 运行 `MAP_SHARED` 版本；在第一次回车前，用终端 B 执行 `od` 和 `cat`，观察另一进程通过页缓存看到的变化：

```bash
cc -O1 -g3 -Wall -Wextra -Werror map_edit.c -o map_edit
./map_edit shared "$tmpfile"
# 终端 B：
od -An -tx1c "$tmpfile"
```

4. 重建临时文件，用 `private` 重复。程序自己的映射中应看到 `MMAP`，但文件内容不应被修改；对 `MAP_PRIVATE` 调用 `msync` 也不会把私有 COW 页写回该文件。
5. 再写一个最小 `write_edit.c`，用 `pwrite(fd, "WRIT", 4, 0)` 修改同一文件，分别在调用 `fsync(fd)` 前后用另一进程读取。注意“另一进程可见”只说明页缓存一致，不等于突然断电后已持久化。
6. 用复制出的临时文件做异常退出对照：修改后不调 `msync/fsync`，直接 `_exit(1)` 或发送 `SIGKILL`。记录“本次仍然看到了数据”不能证明持久化保证；真正的掉电测试需要可丢弃的 VM/文件系统和更严格的实验设计。
7. 完成后删除本实验的临时文件：

```bash
rm -- "$tmpfile"
```

结果解读边界：`MAP_SHARED` 修改可通过同一页缓存被其他进程看到；`msync(..., MS_SYNC)` 同步该映射范围的脏页；`fsync(fd)` 要求同步该文件的数据和必要元数据。若还要保证新建/重命名后的目录项在掉电后存在，通常还需对父目录调用 `fsync`。具体持久性仍受文件系统、挂载选项和存储设备影响。

**完成标准**：用一张表记录 `write`、`MAP_SHARED`、`MAP_PRIVATE` 在“本进程可见、其他进程可见、写回文件”三方面的结果，并分清 visibility 与 durability。

## 第 4 周：综合项目 mini shell

### 最小需求

- 解析命令与参数；明确说明不支持完整 shell quoting 也可以。
- fork + exec 启动程序。
- 支持一个管道和 `>` 重定向。
- 正确关闭所有无用 pipe fd，否则 EOF 可能永远不到来。
- `SIGINT` 不应直接杀死 shell 本身；前台子进程应能收到信号。
- 回收所有子进程并报告退出码。
- 对系统调用错误给出包含 `errno` 的信息。

### 测试清单

```text

参数：           printf '%s\n' a b
重定向：         echo hello > /tmp/out

不存在的程序：   no-such-command
被信号终止：     启动 sleep 后发送 Ctrl-C
压力：           连续执行 1000 个短命令并检查 zombie
```

### mini shell 实操步骤

本项目不建议一次写完。每一阶段都应能独立编译和测试，并创建一个 Git 提交。

#### 步骤 1：建立骨架与输入循环

1. 进入 `~/lab/c-sys/minishell`，创建 `shell.c`、`Makefile` 和 `tests/`。
2. 使用 `getline()` 读取一行；交互模式显示 `mini$ `，非交互模式不显示 prompt。用 `isatty(STDIN_FILENO)` 判断。
3. 空行继续，EOF 正常退出，内建命令 `exit` 结束 shell。
4. 第一版可用 `strtok_r()` 仅按空白分割，并在 README 明确说明不支持引号、转义、变量展开、glob 和命令替换。

建议编译选项：

```make
CC ?= cc
CFLAGS := -std=c11 -D_POSIX_C_SOURCE=200809L -O1 -g3 \
          -Wall -Wextra -Werror -Wpedantic
LDFLAGS :=

minishell: shell.o

clean:
	rm -f minishell shell.o
```

验证：

```bash

printf '\nexit\n' | ./minishell
printf 'exit\nignored\n' | ./minishell
```

#### 步骤 2：单命令 fork/exec/wait

1. 解析结果组织为以 `NULL` 结尾的 `argv[]`。
2. `fork()` 后，子进程调用 `execvp(argv[0], argv)`。`execvp` 失败时用 `dprintf` 打印 `strerror(errno)`，然后调 `_exit(127)`；不要在子进程中调 `exit()` 重复刷新父进程的 stdio buffer。
3. 父进程用 `waitpid()` 重试 `EINTR`，通过 `WIFEXITED/WEXITSTATUS` 和 `WIFSIGNALED/WTERMSIG` 解码状态。
4. 约定 shell 的状态码：普通退出传递子进程退出码，信号终止记为 `128 + signal`，执行不存在记为 127。

验证：

```bash
printf '/bin/echo hello\nexit\n' | ./minishell
printf '/usr/bin/printf %%s\\n a b\nexit\n' | ./minishell
printf 'no-such-command\nexit\n' | ./minishell
```

#### 步骤 3：`>` 输出重定向

1. 解析时将 `>` 当成独立 token，第一版要求用户在其两边加空格。拒绝缺少文件名、多个 `>` 或 `>` 后还有额外参数的输入。
2. 子进程在 exec 前调用：

```c
int out = open(path, O_WRONLY | O_CREAT | O_TRUNC, 0666);
if (out == -1) { /* 打印 errno，_exit(126) */ }
if (dup2(out, STDOUT_FILENO) == -1) { /* 处理错误 */ }
if (close(out) == -1) { /* 处理错误 */ }
```

`0666` 还会受进程 `umask` 限制。

验证：

```bash
printf '/bin/echo hello > /tmp/minishell-out\nexit\n' | ./minishell
cat /tmp/minishell-out
stat -c '%a %s' /tmp/minishell-out
printf '/bin/echo bad >\nexit\n' | ./minishell
```

#### 步骤 4：一个管道

1. 将输入按单个 `|` 分成左右两个命令，拒绝空命令、多个管道和超出项目范围的语法。
2. 父进程先 `pipe()`，再产生两个子进程。左子进程将 `fd[1]` dup 到 stdout，右子进程将 `fd[0]` dup 到 stdin。
3. 每个子进程在 `dup2()` 后都关闭原始的 `fd[0]` 和 `fd[1]`；父进程在两次 fork 后也立即关闭它们，然后分别 `waitpid()`。
4. 默认返回右侧命令状态。若要实现类似 `pipefail`，需要在 README 明确状态合成规则。

验证：

```bash
printf '%s\n' '/usr/bin/printf b\na\n | /usr/bin/sort' exit | ./minishell
printf '/usr/bin/yes | /usr/bin/head -n 1\nexit\n' | timeout 3 ./minishell
```

第二条若超时，首先检查父进程或子进程是否遗留了管道写端。

#### 步骤 5：信号与前台作业

1. shell 本身在交互模式忽略 `SIGINT`。子进程在 exec 前将 `SIGINT` 恢复为 `SIG_DFL`，否则忽略信号的设置会穿过 exec 保留。
2. 基础版可以依赖终端将 `Ctrl-C` 发给 shell 与子进程所在的前台进程组：shell 忽略，子进程终止。
3. 进阶版为每个 pipeline 建立独立进程组，用 `setpgid()` 和 `tcsetpgrp()` 移交/收回控制终端；这是完整 job control 的起点，不是本章强制要求。

手工验证：在 mini shell 内执行 `sleep 30`，按 `Ctrl-C`，应返回 prompt；再执行 `echo alive`，shell 应仍然可用。

#### 步骤 6：资源、错误与压力检查

1. 把每个失败分支都过一遍：`getline`、`realloc/calloc`、`open`、`pipe`、`fork`、`dup2`、`close`、`execvp`、`waitpid`。错误消息至少包含操作名和 `strerror(errno)`。
2. 用 sanitizer 与 Valgrind 运行非交互测试：

```bash

```

3. 生成 1000 条短命令，不依赖 shell 自己支持循环：


**完成标准**：原测试清单全部通过；sanitizer 无报告；无持续 zombie；管道不挂起；`Ctrl-C` 终止前台子进程后 shell 仍可用。
